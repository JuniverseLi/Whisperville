# Audited live town · v1

当前真实运行协议为 `live-town-v1`，使用 `private-life-v1` 的消息来源与四轮交流机制。实现参考 [Generative Agents](https://arxiv.org/html/2304.03442v2) 的感知、记忆、交流与重新规划循环，不声称完整复现原论文。小镇界面仅使用真实 API，使用独立的 `whisperville.live-observation.v1` 存档。

## 一次会面的流程

1. 居民实际走到彼此身边，每段最多结算一场会面，其他居民保留自己的活动。
2. 双方轮流发言四次。每次请求只有当前居民的目标、个人记忆、反思、日程、个人已接收的消息及本次已说出的对话。公开名册仅包含名字和 ID。
3. 服务端验证消息来源。问题与回应不改变场景认知；信息转述必须引用自己的接收记录或本场先前实际收到的消息。可靠性继承来源，模型不能自行升级。
4. 对话整体完成后提交；同场较早消息可以成为较晚消息的来源。其他会面仍须等待下一段。气泡按句播放，来源树保留每次信息转述，完整对话另含普通回应。
5. 模型可提出下一行动、反思与有依据的日程变更。只修改该居民的日程，保存变更原因与引用，标记计划、实际到达或错过。尚未收到决策的居民保持等待状态；不使用默认规则假扮模型决定。开局身份、日程与初始消息属于场景设定，初始消息标为 `scenario`。

## 感知范围

`perception.js` 检查六格范围、相同室内／室外区域和步进遮挡，最多记录五项观察。观察可以描述附近居民的位置和可见走动，不能读取其想法、记忆或未说出的消息。当前尚无完整物品状态模拟或听觉模型。

## 请求预算与失败

一场四句交流用四次独立请求，安静时段轮到一位居民做个人规划，用一次请求。开始前检查完整交流所需额度；每次尝试都计数，包括失败。取消页面请求会中止正在等待的服务请求并停止后续轮次。每游戏仍受原配置上限约束，进程总上限 120 次、并发两次，不自动提高额度。

未完成的模型交流不提交；配置缺失、格式错误或额度不足会暂停，重试由用户手动触发。每次模型输入在发送前写入 `.whisperville/observations/`，返回后保留原始文本、用量、解析结果、失败原因和 SHA-256。完成的段可离线重建输入、逐句投递与认知变化。服务重启会从审计记录恢复该游戏的请求计数和已完成段，避免重复消费。导出观察记录会同时打包当前运行的审计文件。

API：`GET /api/observations/:id` 读取记录，`GET /api/observations/latest` 读取最近记录，`POST /api/observations/:id/replay` 零新增调用核验。也可使用 `npm run replay:town -- docs/results/live-town-run-v1.json`。

## 版本与验证

旧规则实验仍使用 `rule-diffusion-v1`，不改变已发布结果、原始响应或校验和。新生活协议不能直接沿用旧实验的指标结论。

`tests/cognition.test.mjs` 用本地 HTTP 模型替身检查上下文隔离、逐次消息投递、同场来源链、个人计划引用、预算与 72 段存档有效性；它们是实现验证，不是新模型实验结果。`speech.test.mjs` 检查逐句顺序、暂停和阅读计时。真实模型输出仍可能出现不自然表达；来源校验约束结构，不能证明文本语义完全一致。

`tests/live-observation.test.mjs` 检查真实模式不补答、发送前审计、失败保留、脱敏、回放与重启后额度恢复。[本次真实运行](results/live-town-run-v1.json)为一个种子的三段记录、9 次真实请求、两场会面；没有对照，不是一般性的效果结论。

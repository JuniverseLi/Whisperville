# 耳语镇的研究方向

目标是把小镇发展成**可以提出问题、控制条件、复跑和核查的多智能体实验沙盒**。好玩的观察界面与实验记录共用基础规则；日常观察和批量实验分开呈现。

## 从 Scaling Swarms 学什么

[s³: Simple Scaling of Swarms via Cooperative Multi-agent RL](https://scalingswarms.com/)研究无预设角色的异步语言模型群体，通过共享团队奖励训练协作，并采用等预算基线、规模变化和通信消融来检验效果。网站提供[预印本](https://scalingswarms.com/paper.pdf)。它报告的是经过训练的群体；耳语镇目前没有训练模型，不能声称复现了它。

适合借鉴的是方法：先明确问题和成功条件，匹配资源预算，保留逐次轨迹，用对照和消融排除其他解释。小镇是观察与干预环境，研究价值取决于这些可检验的机制。

## 已实现的第一项实验

**问题：同样额外向一个居民提供可靠公告，随机选择、最高出度选择和最高中介中心性选择，有何不同？**

- 固定 25 人与有向联系人网络。初始林朵有传闻，乔安有可靠公告。
- 默认种子 `1000–1029`、12 段、在完成第 2 段后且开始第 3 段前介入。
- 四个条件：不额外介入、随机居民、最高出度居民、最高中介中心性居民。
- 三个介入组从当时尚未核实的居民中选人，各花一个单位；对照组花零个单位。中心性由固定有向网络计算，平分时按 ID 决定。
- 同一初始种子跨条件配对；随机选人的随机流与传播随机流分开。
- 指标包括最终可靠来源覆盖、未核实传闻占比、时间平均覆盖 AUC、居民转述次数与最长可靠来源链。AUC 用记录点的梯形积分归一化；介入时点记录介入后的状态。
- 每个均值使用 1000 次百分位自助法区间；与随机策略的 AUC 差异先按种子相减，再重采样配对差异。曲线展示种子均值。区间描述这些模拟种子的变异。
- JSON 保存配置、规则版本、网络、个人谨慎参数、每次介入对象、逐段指标与完整消息来源链。CSV 每行对应一个种子和一个条件。

## 怎样复跑

界面：**设置 → 传播实验室 → 运行配对实验 → 导出 JSON / CSV**。计算在 Worker 中进行，可停止，不读取 API 密钥、不调用模型、不改变当前小镇存档。

```sh
npm run experiment -- --seeds 30 --rounds 12 --seed-start 1000 --intervention-round 2
python scripts/plot-experiment.py output/experiments/report.json
```

Node 命令写入 `output/experiments/report.json` 与 `trials.csv`，再次运行会覆盖这两个生成文件。绘图脚本需要 NumPy、Matplotlib，输出独立 PNG / SVG；图中曲线区间使用固定 NumPy 种子的百分位重采样，配对差异区间直接读取 JSON。应同时记录所用代码版本；变更规则或统计定义时更新 `EXPERIMENT_VERSION`。未经真实运行的数据不用于结果图。

## 先看清传播，再解释指标

主界面的「传播图谱」按实际消息来源树呈现，而不是把可能的社交关系画成传播。每张卡片是一次接收记录，箭头对应父消息，节点按转述跳数分列。可以筛选初始源头／外部介入根，选择消息查看接收者的前后认知与完整来源链，并沿记录时间轴回看。

触达人数是去重接收者数（包含初始持有者）；当前可靠来源／未核实占比通过按序重放记录得到，不拿最终状态替代历史。转述类别变化按子消息与父消息的 `claim` 标签比较，尚无独立的语义失真评估。认知纠正要求收到可靠转述前已有未核实认知。闲聊不计入场景扩散。可导出事件级 CSV 供二次分析。

[公开结果与完整数据](results/README.md)同时披露规则运行、已完成真实 API 试跑和此前输出截断的失败记录。README 中的传播图采用[固定接触序列示例](examples/propagation-walkthrough.json)，用于演示读图，不作为新实验结果。

## 当前结论的边界

这一实验运行**抽象接触网络中的规则传播**，不包含像素地图寻路、居民日程、模型决策或强化学习。把可靠来源设为不可被传闻覆盖，是我们写进引擎的约束，不是模型学会了求证。联系人按引擎优先级和每段三次接触上限选择，也不是现实接触数据。

因此它可以检查本模拟机制中的策略差异，不能证明大模型会自主合作，也不能外推现实社会。节点性格与网络位置并未随机打散，策略差异也不能解释为中心性本身的单独因果效应。单一网络、一个场景或 30 个种子都不足以形成一般结论。增加种子、改变参数与独立复跑，应先于解释“哪种策略更好”。目前不比较居民规模，不做训练或真实人类验证。

## 已接入的真实模型协议试跑

新增 **真实模型** 页签，通过本机配置的云端 Chat Completions 接口逐个调用居民。四人各有一个 10–99 的唯一私有整数，团队目标是任意一人提交完整的有序列表。每个任务种子先固定同一组私有输入，再运行允许通信和禁止通信两个条件；每条件四人各两次调用，共 16 次／种子。默认仅一个种子，最多三个，用于连接和协议验证，不生成显著性结论。

每人的模型请求只含自己的数值、公开的同伴 ID、自己的历史回答与上一轮已投递的消息。所有人的该轮请求结束后才投递，避免顺序泄漏。禁止通信条件即使模型尝试发信也不会投递。正确性由完整列表的精确匹配决定，程序不补答案、不提供教师答案、不自动重试。输入语言固定英文，界面语言不改变任务条件。

审计记录含每次请求及 SHA-256 摘要、原始模型文本、解析动作、实际报告的用量、耗时与失败状态。模型未报告的 token 用量为 `null`；没有价格配置时不推算费用。正常完成才给出回放通过标记，回放重新构造私有提示并验证消息投递与评分，不访问模型。任务种子不保证远端模型输出可复现。

这不是 s³ 的训练复现：当前有固定轮次与人数，没有异步调度、共享奖励或模型训练。禁通信使私有信息不完备，故此任务首先验证信息传递链路和信息利用，而不是一项等可解性的通用能力优越性证明。模型失败、取消或格式错误保留为未完成，不混入规则实验统计。后续应扩展任务难度、独立可解的同预算基线与足够重复次数。

## 下一阶段的三个可检验问题

| 问题                                   | 需要补的实验条件                                                        | 可用指标                                      |
| -------------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------- |
| 交流是否帮助找猫，而非只是增加搜索者？ | 多人各有不完整线索；可交流／禁交流；相同搜索和 token 预算；独立搜索基线 | 找到率、重复搜索、通信代价                    |
| 记忆与反思是否改变协作？               | 同一批任务与模型，完整／去检索／去反思消融；记录原始模型请求与返回      | 成功率、计划实现率、成本、消息利用率          |
| 人多何时带来收益，何时只增加协调负担？ | 可变人口与匹配预算；重复任务实例、多个种子；小组与独立 best-of-N 对照   | 随规模变化的成功率、延迟、总 token 与重复工作 |

真实试跑和日常观察现在均按居民独立构造模型请求。日常生活协议升级为 [`private-life-v1`](private-life.md)，增加局部感知、四轮交流与有依据的日程修改；当前小镇进一步使用 `live-town-v1`：只提交真实模型返回，失败暂停，逐次记录输入、原始响应、用量与回放。本次单种子三段运行有 9 次真实请求，但没有对照，不能形成一般效果结论。规则实验的 `rule-diffusion-v1`、已公开统计和原始模型试跑保持独立。后续实验应原样保留请求与返回，区分真实 API、回放、规则接管和失败。相同种子不能保证远端模型逐字复现。奖励设计和多智能体强化学习属于更后续的训练工作，不能由改提示词替代。

## 真实小镇运行记录

当前主要实测数据为 [live-town-run-v1](results/live-town-run-v1.json)。2026-11-07 16:35（Asia/Taipei），seed 42，学校传闻场景，完成一次私人规划和两场四句会面，9 次请求均成功，总计 29,399 token。触达从初始 2 人增至 3 人，传闻沿林朵 → 米娅 → 林朵返回；可靠来源未继续扩散，没有认知纠正、日程修订或反思。仅两名居民获得模型决策，其余 23 人仍等待。

这是真实 API 流程与传播记录验证，不是完整一天或统计对照实验。每个完成段均可离线重建请求、解析原始返回并核查状态，命令为 `npm run replay:town -- docs/results/live-town-run-v1.json`。下一项可检验研究应在同预算下增加独立种子和通信／记忆／反思对照，而不是把一次顺利运行当作能力优势。

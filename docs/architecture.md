# Architecture

## Pixel world and interaction

`src/game/map.js` defines a 72 × 50 grid with 16-pixel tiles, eight accessible cutaway interiors, river crossings, furniture and collision data. Breadth-first search produces cardinal routes on walkable tiles. Approaching a resident targets an adjacent tile; keyboard movement checks the player's footprint against walls and furniture.

`paint.js` caches the original tile map into an offscreen canvas and renders 3-column × 4-row character sheets with image smoothing disabled. Row order is south, west, east, north; columns are step, idle, opposite step. Frames render at 46 × 46 to preserve their square aspect ratio. `characters.js` derives 17 outfit palette variants from the eight original sheets and caches them. Assets are copied unchanged to `public/pixel/characters/`; prompts and generation provenance are in `docs/pixel-art-prompts.json`.

`environment.js` reads the unchanged 4 × 2 building and 4 × 4 prop atlases from `public/pixel/environment/`. It finds each cell's nontransparent bounds and caches sprites at one pixel per world pixel, using nearest-neighbor sampling throughout. A half-resolution intermediate or smoothing would blur buildings against the ground. `docs/environment-art-v2.json` records prompts, grids and source paths. Tile collisions remain authoritative; transparent image margins do not define collision boxes.

`landscape.js` defines the shared scene palette and builds native pixel-art grass, earth and water materials. Buildings and props are quantized to the same 40-color palette, with isolated specks removed while retaining dark outlines and transparent edges. Outdoor paving is assembled from individual small slabs over earth, with gaps and moss at the perimeter, rather than covering a rectangle with a stone image. Cached contact shadows and worn ground bind stationary objects to the surface. Shallow shoreline overlays vary riverbank silhouettes while skipping the bridge crossings; collisions stay unchanged.

`terrain.js` retains the 3 × 2 material atlas recorded in `docs/terrain-art-v3.json` for indoor wood/stone and soil accents. Outdoor materials come from `landscape.js`. Sampling uses global coordinates rather than restarting textures at every grid cell. A deterministic signed-distance mask gives walkable grass/earth boundaries irregular silhouettes, with sparse blade clusters at the edge. Edge runs and the painted map are cached.

`createOutdoorMap` derives a separate, immutable outdoor surface beneath the buildings. `paintOutdoorGround` renders its shared edge mask once. The cutaway map restores interior floors on that surface; each exterior backing copies the exact corresponding outdoor pixels, including road corners. Never fill a roof backing with a plain grass rectangle: it would overwrite neighboring paths and introduce hard rectangular seams. Pixel checks compare all eight roof backings against the shared outdoor layer.

The observer defaults to cutaway interiors; V toggles exteriors. Ground backings are composited immediately after the static background, before every person. Only transparent building sprites join the depth-sorted furniture/tree/person pass. Combining the opaque backing with the roof sprite would erase a nearby character's legs even where the roof image is transparent. Interior props and residents fade with roof opacity. A failed art load retains native fallback rendering.

`world.js` owns the animation loop, observer camera and NPC movement. Live refs avoid rebuilding the world on React updates. Playback, single-segment stepping, modal panels and hidden tabs control updates. Speed scales movement and simulation time. Selecting a resident works while paused; following moves only the camera. Residents physically approach their planned partners before a conversation commits, and each person participates in at most one simultaneous conversation. Other residents travel to their intended locations. Pausing during a model request prevents another segment, while the completed request can still save the current segment.

`TownObserver.jsx` is the active UI: scene controls, actual actions, intended actions/reasons, received-message memories and provenance. `life.js` defines role goals, legal destinations, context construction and strict intention validation. The unconfigured model path uses explicitly labeled deterministic routines. Earlier `PixelGame.jsx`, player sessions and scripted dialogue remain as inactive legacy code; the shared world runtime still supports their controls for regression checks.

`camera-controls.js` separates taps from captured pointer drags with a six-CSS-pixel threshold. Drag and wheel work while simulation playback is paused but stop behind modal dialogs. A drag releases resident following; a tap still selects. Wheel zoom keeps the pointed world location anchored where camera bounds allow, normalizes line/page units and bounds zoom to 0.5–3×. Observer camera centers stay within the world rectangle, allowing panning even at the full-map scale. Pointer cancellation, capture loss and disposal never trigger a selection. The legacy player runtime retains its original controls.

`StoryChooser.jsx` introduces the four starts on first entry; `whisperville.welcome.v1` stores only whether that introduction was seen. The toolbar reopens story selection and help. The main story card gives actionable suggestions for looking around, inspecting a resident, stepping a segment and tracing a conversation; the guide collapses after completion. Opening the chooser pauses the world, and changing a scenario creates a fresh run only when the user confirms the selected card.

## Transmission observatory

`propagation.js` replays committed scenario messages in stored order up to a segment cutoff, preserving same-segment interventions. Each event exposes the receiver's belief before/after, whether evidence protection blocked a rumor, a source root, depth and claim-category changes. This replay intentionally excludes casual encounters. Counts include initial message holders. A category change is a structured label change, not an NLP semantic-distortion measure.

`cascadeLayout` builds only exact parent-message edges, arranged left-to-right by hop and vertically by descendants. Social graph links never become event edges. `PropagationView.jsx` provides source filtering, recorded-segment playback, before/after inspection, chain highlighting, resident location and CSV export. History mode does not advance simulation or call a model. The separate Next segment control runs the normal physical meeting loop; the observatory follows new committed segments only when positioned at the latest record. Opening pauses continuous play.

`App.jsx` passes actual actor snapshots through `commitLiveTurn` and `advanceCognitiveTurn` so newly committed messages can retain optional `pixelMeeting` coordinates. Canvas arrows for the last segment use these recorded positions, not moving actor positions or legacy abstract village metadata. Existing saves and abstract experiments without physical coordinates render no fabricated map arrows. `scripts/propagation-walkthrough.mjs` generates a labeled, fixed-contact rule walkthrough for documentation screenshots; its saved example is not a live API experiment.

## Simulation authority

`src/simulation/engine.js` implements pure state transitions. `planTurn` resolves up to three non-overlapping meetings from validated resident intentions; legacy callers retain seeded contact selection. `advanceTurn` and `toModelConversations` use the same intentions. New recipients cannot forward within the same turn. Verified evidence cannot be fabricated by model output or overwritten by rumors.

Every forwarded message points to its actual source through `parentId`. Official evidence creates a new source root. The legacy school scenario seeds the teacher with a genuine official notice and the café owner with an uncertain rumor. Showing evidence costs one of three copies unless the recipient already knows the fact.

Observation supports 72 segments, including quiet periods without messages. All residents learning the fact does not end their daily activity. The legacy exploration/twelve-round rules remain covered by tests. `village.js` retains earlier abstract meeting metadata, which is distinct from actual pixel positions passed to model context.

`scenarios.js` defines four allowlisted starting situations. `scenarioId` selects seeds, source holders, claim meanings, localized story text and optional destination progress. Missing scenario IDs in older saves retain school behavior. The spring party starts with Lin’s invitation; the missing-cat scene starts with a riverside rumor and Zhou’s flower-shop sighting; free living has no seeded messages and no evidence interventions. Historical rule tools let hosts contact uninformed neighbors. The active live UI keeps residents pending until a real model decision arrives. Model intentions remain authoritative for model mode. `recordStoryProgress` records unique arrivals from actual snapshots at the designated venue after its start segment, requiring a reliable clue for the cat. Knowing a location alone never marks an arrival. `story-art.js` renders a small clickable cat or tea sign in the corresponding interior, without changing collision geometry.

Conversation inputs carry only the sender’s allowed `claimMeanings`, so new scenarios do not inherit the school message taxonomy or disclose the verified meaning to rumor-only speakers. Casual chat remains `claim: null`; all source-chain and verification rules still apply.

## Model boundary

The active town uses `live-town-v1` with the `private-life-v1` cognitive transition rules. `live.js` initializes scenario information and pending intentions, then commits audited real responses only. `App.jsx` sends bounded personal contexts to the local `/api/turn` orchestrator. `server/cognition.mjs` gives the remote model exactly one resident's context per request: own goals, sources, six retrieved memories, two reflections, nearby observations and the dialogue already delivered during this meeting. The public directory contains names and IDs only. Four alternating utterances use four independent calls. Quiet periods select one resident for one personal planning call. Only residents who made decisions receive model intention updates; others follow their own ongoing schedules and labeled rules.

`perception.js` checks six-tile range, room boundaries and walkability-based occlusion, returning at most five visible observations. Other residents' memories and intentions are never perceptual events. `cognition.js` commits complete dialogues, preserves source ownership and permits same-segment parent edges only between ordered turns within the same conversation. The versioned observer settles one meeting per segment; legacy rule experiments retain up to three simultaneous meetings and their original semantics. Incomplete model dialogue is discarded and the town pauses. `observation-audit.mjs` persists each private request before sending, raw returned text and usage, parsed actions and deterministic state transitions. Completed traces replay without provider access; audit ledgers restore per-game counts and prevent completed-round repeats across restarts.

`memory.js` stores up to 100 memories and 12 reflections per resident. Direct observations record actual locations and visible nearby activity; received/sent messages and casual encounters are recorded only after commitment. Retrieval combines recency decay, rule-based importance and lexical overlap, not embeddings. Retention removes reflections whose citations expire. Reflections remain personal inferences and never establish verified beliefs. Four baseline schedule entries are rule-generated. `applyDayPlans` accepts cited future schedule revisions, replaces conflicting start slots and records reasons. Up to twelve schedule slots and twelve revisions persist, with planned/completed/missed statuses based on actual location and time. This is bounded replanning, not the original full hierarchical planner.

Uninformed residents can also initiate a real meeting. Casual conversations use `kind: chat`, `allowedClaims: [null]` and a separate `encounters` log; they cannot update scenario beliefs or become rumor source roots. Information-bearing messages retain the strict original `parentId` source chain. Both participants retain a memory of casual dialogue.

Credentials remain server-side. `GET /api/config` exposes only masked configuration; `POST /api/config` validates and persists settings with atomic replacement in `.whisperville/api.json`; `POST /api/config/test` performs a 16-token connection check. Stored settings override environment configuration and take effect without restart. A blank key is retained only for the same endpoint. The secret folder is excluded from Git, Vite and the production static directory.

Requests enforce same-origin checks, byte-size bounds (16 KiB settings/legacy input, 256 KiB local context bundle), timeouts, two concurrent provider calls, per-game budgets and a 120-call process budget. Budget checks reserve capacity for an entire conversation before starting; every actual attempt consumes one unit. Read bodies as buffers and decode once so Chinese UTF-8 characters are not split across chunks. Individual observation calls allow 1,400 output tokens and 30 seconds; connection checks allow 15 seconds. Client disconnection aborts the current request and prevents later turns. An asynchronous reply cannot replace a restarted game. The service binds to loopback; public multi-user deployment is outside this prototype.

`Language.jsx` persists `zh`/`en` independently of simulation saves. `src/i18n.js` localizes profiles, places, beliefs and messages. New model output must supply both language fields; generated records remain unchanged when the viewer switches languages. The Canvas receives both current activity translations, and cached map signs rebuild when language changes.

## Offline research baseline

`experiments.js` runs four paired intervention conditions over a fixed 25-node directed social graph. It reuses the school scenario and source-chain transitions while deliberately omitting life intentions, rendering, physical travel and models. Each seed starts with the same rumor and teacher notice. After a configured segment, active policies select an unverified target using a separate seeded random stream, highest out-degree or directed Brandes betweenness; each spends one notice. The control spends none. The observer flag prevents early termination so all conditions run the same horizon.

Outcomes include final source/rumor coverage, normalized trapezoidal coverage AUC, resident retelling count and maximum evidence-chain depth. Summaries use 1,000 nearest-rank percentile bootstrap resamples over simulation seeds; policy-minus-random differences are paired by seed before resampling. All trial messages and histories remain in JSON alongside graph/caution parameters, protocol assumptions and `EXPERIMENT_VERSION`. Change the version when behavior or statistical definitions change. Rule-based evidence protection is an assumption, not an observed LLM capability.

`experiment-worker.js` isolates computation from rendering and can be terminated by the dialog or cancellation button. It never calls providers or modifies the active game. `ExperimentLab.jsx` is retained for historical rule work; the main Settings entry now opens real town audits. `scripts/experiment.mjs` runs the same core from Node and writes JSON/CSV. The optional Matplotlib script generates standalone figures from those actual exported trials. Browser checks verify worker completion/cancellation, downloads, unchanged town saves, mobile layout and zero model requests. See `docs/research.md` for protocol and limitations.

## Live model protocol pilot

`model-study.js` defines a four-resident private-number aggregation task. A seed fixes task inputs, not model sampling. The two conditions share private numbers, two synchronous rounds, request count and a 1024-output-token cap. A resident request includes only its own private number, its own prior answers and messages delivered after earlier whole rounds. No shared batch prompt contains all private inputs. Disabled communication is enforced by not delivering messages. Exact matching to the sorted ground truth grades submitted answers; incorrect or absent answers are never repaired.

`server/model-study.mjs` calls the configured Chat Completions provider, reserves the shared process/concurrency budgets, persists each request before sending and records ordinary model content, reported usage, timing, parsed action and sanitized failures. Provider-reported model and response IDs are retained when present; unknown usage stays null. Authorization headers and keys are excluded. One study runs at a time; client IDs prevent repeat starts after acceptance. Cancellation aborts in-flight work and prevents later calls. A fixed snapshot of the configured provider is used for the job. Missing configuration, malformed responses, budget failures and interruptions cannot become successful rule-fallback results.

Jobs stay under `.whisperville/model-studies/`; restart does not resume paid requests. `ModelStudy.jsx` polls progress, can cancel, downloads raw JSON and remembers only the last report ID in browser storage. Replay reconstructs private requests and message transitions, verifies request hashes, reparses recorded model content and recomputes scores without network access. It verifies trace consistency, not cryptographic proof of which remote model served a response. The CLI uses the same replay verifier. The four-agent pilot is zero-shot and synchronously scheduled: it has no shared-reward training, and its information-incomplete no-communication control is not a broad claim of cooperative superiority.

## Saves and verification

The browser stores strict live runs separately in `whisperville.live-observation.v1`, preserving earlier `whisperville.observation.v2` demonstration saves; the older RPG save keys remain separate. Refresh restores beliefs, intentions and messages, pauses playback, and restarts residents from home. Corrupt intentions, personal memories or game state trigger a new run. JSON export includes the live state and all associated raw audit records; import is not implemented.

Run `npm test`, `npm run build` and `npm run format:check`. Tests cover pointer drag/tap separation, cancellation, wheel normalization, four scenario seeds, actual arrival checks, free living, valid intentions, changed contacts, bounded private memories, quiet periods, quotas, HTTP model parsing and simulation invariants. Browser checks cover mouse dragging (including from a resident), wheel/button zoom, mobile touch, first-visit guidance, all four story switches, actual party attendance, 25 residents, search, playback, pause, speed, stepping, bilingual switching/persistence, inspection, provenance, responsive controls, API form save/test and a mocked-model decision reaching an actual Lin–Qiao meeting. No real paid provider is required for verification. A separate pixel regression compares a character above a building corner with its unobstructed sprite to detect ground-mask occlusion.

## Published artifacts

`docs/results/` carries measured rule summaries, compressed full rule trials, sanitized live-pilot task requests/outputs and the earlier failed calibration. `export-research-artifacts.mjs` copies existing runs through explicit field allowlists, verifies completed-model replay and emits SHA-256 hashes. It never calls a provider. Generated audit JSON is excluded from format mutation so hashes remain stable. `tests/research-artifacts.test.mjs` checks integrity, table rounding, replay and message counts. Screenshots of the observatory use a clearly labeled fixed-contact walkthrough, not new paid runs.
